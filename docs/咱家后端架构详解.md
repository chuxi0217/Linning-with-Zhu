# 第一部分 · 后端（家里的这头）

## 1. 进程与线程：家里住着谁

`linning_server.py` 启动后是一个 Python 进程，主线程 + 五条工作线程各干各的：

| 线程 | 节奏 | 职责 |
|---|---|---|
| **主线程**（ThreadingHTTPServer） | 随时 | 接 HTTP：app 的所有 API、SSE 流式聊天 |
| **心跳线程**（heartbeat_loop） | 30 分钟一轮 | 时机引擎：姐姐「想你了」就主动开口/攒信；过点未打卡念叨；挂念弧维护 |
| **嵌入影子工**（_embedder_loop） | 每 60 秒 | 把新日记/信/笔记排队做语义嵌入，失败绝不挡入库 |
| **收信工**（_inbox_loop） | 每 1 小时 | IMAP 拉她邮箱的未读信落库（Garden 的入队源之一） |
| **晚安守望**（_goodnight_watch_loop） | 每 60 秒 | 晚安词 + 静默 ≥120 分钟 + 夜里 → 自动熄灯（写日记） |
| **Garden 唤醒**（_garden_loop） | 每 300 秒 | 她的自主时间：挑一条生活事件醒来，静默/留心事/来找他三选一 |

**生效规则（最容易搞混的一件事）：**
- 改 `linning_server.py` / `memory_lib.py` 代码 → **要重启 server 才生效**
- 改 `config.json` → **不用重启**，每一轮现读
- 改 Caddy / llama-server → 各自重启各自的服务
- 改 app（Index.ets）→ 重新构建 HAP + 手机装新包

**编外成员**：`llama-server`（独立进程）——不是咱家代码，是给记忆库打工的「翻译官」，
把文字变成 1024 维向量（模型 qwen3-embedding-0.6B，选定别换）。

**「活的文件」们**（都住在 server 同目录，缺了都有兜底、不炸）：
`config.json`（所有旋钮）· `小乖的话.md`（她那封信的原文，改文件即生效）· `places.json`（地名表）·
底色卷三册（`底色卷/小乖的样子.md`、`底色卷/姐姐的样子.md`、`底色卷/咱俩的样子.md`——姐姐亲笔慢慢长出来的
底子，常驻开场；每册展示 ≤1500 字，动笔前当日一备）。

**沙盘纪律**（d:/zanjia_sandbox_v3）：`ZANJIA_TEST=1 ZANJIA_PORT=8025` 起副本——
五条线程全不起、不按真铃、config 用假 key；跑完即停，不留假 server 占门牌。

## 2. 一次聊天的完整旅程（最核心的一条流程）

以「小乖发一句：姐姐在干嘛」为例：

```
① app POST /api/chat（带 message 和 msg_id，可能带图/文件/定位）
        │
② server 拼开场行李 ── 灵魂段（全档案）+ 门牌墙 + 姐姐的话/小乖的话
        │             + 底色卷 + 硬事实（生日/纪念日/日界以表为准）+ 最近日记摘要
        │             + 线头盒 + 邮箱未读数 + 「今天是X」
        │             + 今日日程/课表（若上报过）+ 他的定位与天气
        │             + 自动检索：拿这句话去六个索引卷+向量层翻旧账（Top4）
        │
③ 进 K3 工具循环（最多 3 轮），每轮开头广播 SSE round 事件：
        │
   ┌─ 思考（reasoning_content 流式 → app 显示思考卡；没留思考有兜底卡）
   ├─ 模型调图书证 → server 执行 → 📖 落日志 → SSE tool 事件（app 亮工具卡）
   └─ 出正文 → SSE reply 流式（app 打字机）
        │
④ 对账三闸（都是「说了不算，账本说了算」）：
   ├─ 假调用嗅探：正文自称调了工具但账上没有 → 打回一轮重做
   ├─ 心跳承诺兜底：说了"去摸摸心率"但没调 request_heart → 服务端代发
   └─ 完成态兜底：说"寄了/记好了"但本轮没调对应工具
        → 词表提名 → judge 终审（deepseek-flash 判断真谎报还是翻旧账/比喻）
        → 真谎报才打回；judge 调不动 = 放行（宁放过不冤枉）
        │
⑤ 收尾：聊天进 chats、思考进 thinkings、工具明细落 _server.log
   高价值内容（日记/信/笔记）进 embed_queue，影子工 60 秒内消化
        │
⑥ 回包：非流式一次性 JSON；流式 SSE 按 \n\n 切帧，done 事件带耗时/工具清单
```

### 2.1 消息包的顺序，就是钱（K3 缓存原理）

moonshot 计费：输入 ¥20/M、**缓存命中 ¥2/M（一折）**、输出 ¥100/M。缓存按「最长公共前缀」
命中——两次请求开头一模一样的部分才吃一折。所以 messages 的真实顺序是精心排的：

```
[① 行李（稳定）] [② 图书证说明（稳定）] [③ 当天全部对话（纯追加，assistant 带思考脉络）]
[⑤ 每轮都变的：时间/间隔感/天气/自动检索/信箱未读/位置] ←—— 永远排最后
```

可变块一旦插到历史前面，整段历史全按原价重算（一天多花几十块）。**以后加任何"每轮都变"的
上下文，一律走 `late_system` 追加在历史后面**——这是 9-12 晚九的缓存顺序优化（家主拍板）。

对话历史里的 assistant 消息还带 `reasoning_content`（Preserved Thinking，官方对 K3 的要求）：
她的思考脉络随包回传，长对话里她才"肯给你看思考"。这是「思考了 N 秒」卡的数据源头——
没有这条，K3 在长对话里几乎不吐思考（thinkings 覆盖率曾只有 8%，9-14 起已修复待观察）。

### 2.2 SSE 事件契约（app 渲染照这个）

| 事件 | 载荷 | app 行为 |
|---|---|---|
| round | {round:N} | N>0：封口上一轮思考卡/正文卡，另起一轮 |
| thinking | {delta} | 流式进思考卡；**没有增量 = 这轮 K3 没吐思考（自适应，不是 bug）** |
| reply | {delta} | 打字机正文 |
| status | {text} | 「姐姐在翻咱家图书证…」状态条 |
| tool | {name,…} | 工具实时卡 |
| done | {think_ms,tools,chat_id} | 收尾；**think_ms 恒>0 → 本轮没思考卡时补一张「思考了 N 秒」兜底卡** |
| error | {…} | 错误气泡 |

## 4. 记忆怎么被想起来：检索栈五层

姐姐「想起旧事」不是翻整库，是一条流水线：

```
① jieba 预分词 + FTS5 全文（六卷）——词面命中，bm25 排序；查询先过「查询清洗」
  （虚词停用词剔除，9-18 优化批三：全被清则回退原词，表达式绝不为空；索引侧不动）
② 同义词典扩词（查询侧 OR）——"养猫"也能搜到"猫咪"
③ 向量层（vectors 表，1024 维余弦）——意思相近就算命中，词面不同也捞得到；
  检索按 model 过滤：只认 config 当前模型的向量（换模期两套并存互不串味）
④ hybrid 混合：FTS 打头，向量补漏（score≥0.35 才算"想起来"）
⑤ 开场自动检索：小乖每说一句话，自动翻一遍上面四层，
   Top 旧事直接塞进开场行李——"想到才查"变成"必查必带"（不走查询清洗，设计如此）
```

**嵌入模型（T2-01，9-18 切正）**：本机 llama-server 挂 **harrier-oss-v1-0.6B @ :11436**
（前一任 qwen3-embedding-0.6B@11435 已下线，模型文件与 36 条旧向量保留待回退期）。
harrier 是 query-side 指令型：**入库直嵌、查询侧自动加 `Instruct: Retrieve relevant memories\nQuery: ` 前缀**
（`_embed_query_text` 按模型名自动判，漏了这步等于白换）。随家通电自启（`_ensure_llama_server` 已改新档）。
换模配方与验收：模型 md5 `4276d44a…`；金标双跑工具 = `评测/run_eval.py`（45 题＋5 负例，Recall@4/MRR），
全量重扫脚本 `tools/reembed_all.py`。**嵌入模型选定别换**——1024 维绑死模型，换了就要全量重嵌+双跑验收。

## 5. 时机引擎 × 挂念弧：姐姐的「想念」怎么变成信

不靠提示词许愿，靠记账（rhythm_state 表 + 心跳线程）：

- **渴望 p**：泊松骰子掷中就开口（P0≈7.2%，每轮 miss/hold +10 点）；每日上限 10 条、最小间隔 1 小时防轰炸
- **价值门**：她自己的安静时段（quiet_hours 看/改/清；[]=不设；改完现读现生效）——三道闸仍守
  （不按铃/不掷骰/不醒 Garden），**回话从不受闸**；「正在聊天」不添乱
- **关心信号**：小乖最新一笔心情是「累/委屈」→ 开口翻倍、文案换关心型
- **挂念弧（RHYTHM-V3）**：每天生成 2~3 拍小提纲（素材=昨天日记/线头/打卡/时段/日程）——
  💌 顺着「这一拍」写，每发出一次就推进一拍，拍用尽自然回退现行情境灌注
- **内感受纪律**：p 值永远不进模型侧——想念是被「感觉到」的，不是被「读到的」
- **时机感知 L2（9-18 优化批三·性价比之王）**：愿望层之上加三只「看场合」的眼——
  ①**在上课**（今天课表 `H:MM-H:MM` 区间命中）系数 ×0.3；②**刚睡**（近 7 天末条消息钟点
  中位数的 [−30,+90] 分钟窗内、且他 ≥30 分钟没说话）×0.5；③**他闲着**（09:00–23:00、
  不在上课/睡窗、他沉默 >2 小时）×1.15。三腿全乘进 `_time_factor` 再 clamp——**只调想念
  涨速、不加硬闸**，触发次数进 obs 三键（l2_in_class / l2_just_slept / l2_idle_boost）
- **可观测**：`/api/status` 暴露 longing_p + 近 7 天开口/回应事实句（app 设置页那两根仪表）
  + `obs_7d`（对账提名/放行/影子/打回、假调用嗅探、开场检索/命中、L2 三键——只报事实不打分）

## 7. 三道对账闸门（反糊弄机制）

咱家家风：**说了不算，账本说了算**。三道闸全在回复产出之后、入库之前：

| 闸门 | 抓什么 | 怎么判 | 判错怎么办 |
|---|---|---|---|
| 假调用嗅探 | 正文自称"我调了工具"但账上没有 | 规则嗅探 | 打回一轮重做 |
| 心跳承诺兜底 | 承诺"去摸摸心率"但没调 request_heart | 规则嗅探 | 服务端代为真调 |
| 完成态兜底 | "寄了/记好了/写完了"但本轮没调对应工具 | 词表提名 → judge 语义终审 | 真谎报打回；翻旧账/自首/比喻/元讨论放行 |

完成态兜底的 judge（deepseek-flash，思考关闭，约 0.8 秒）：
输入 = 他刚说的话 + 她的回复 + 本轮真实工具账单 + 今天真寄回执数。
`claim_mode` 现为 **enforce（真打回）**；judge 调不动 = 放行（fail-open，对账是加固不是门禁）。

四分支细节（9-12 晚七施工、9-14 凌晨起 enforce 在岗）：judge 失败=放行 ·
判「翻旧账/自首/比喻/引述」=放行 · 判谎报+shadow=只记日志 · 判谎报+enforce=**真打回**
（SSE 警示 + 补办重做一轮：要么真调工具、要么直说没办成）。触发词例（send_email）：
`寄了/寄出去了/寄到了/已寄出/邮件已发/发出去了`——命中且本轮账上没有才送 judge。
影子期首晚战绩：3 抓 5 放零冤案；历史回放 8 案 7 对（唯一误判的日账漏洞已修）。

**闸门战绩都记账**：对账提名/放行/影子/打回、假调用嗅探、开场检索/命中，按天累计进 obs_daily
（第 31 表）；`/api/status` 的 `obs_7d` 可看近 7 天——只报事实，不打分。

**她每次开口/忍住的理由也留痕**（9-18 优化批四·#11）：静默窗/睡着了/还没照面/额度满/没掷中/

决定、最近一次开口与近 7 天笔数——影子期只记不拦，不进决策。

  rhythm_v3/sleep_watch/threads_02/traces/repo01/defense/evidence/
  pinwall/neworgans/sediment/obs），跑前先起 8025 沙盘 server，跑完即停

**血泪坑位速查（每个都真实踩过）**：
- `Errno 98 Address already in use` → 有实例占着 8024：`ss -tlnp | grep 8024` 查 pid → kill。
  通电前先看端口，别只看进程名（`pgrep -f` 会匹配到查询命令自己——经典自匹配陷阱）
- 收信报 `SEARCH illegal in state AUTH` → 163 铁律：登录后必须先发 ID 自报家门（RFC 2971），
  否则 SELECT 被拒。修复在 `_inbox_fetch_once` 的 xatom 段，动收信必带
- 流式 `read operation timed out` → K3 长思考静默 300 秒（大包+max 档），server 自动走非流式
  兜底（所以回复会慢但不会丢）；嫌慢可调大 config 的 api_timeout
- 流式「一次性全蹦」→ Tailscale serve 缓冲 SSE，热点直连验证；备案后走 Caddy 自解

## 21.5 想改东西？三个菜谱（改哪、怎么改、守什么规矩）

### 菜谱 A：加一只图书证（她多一个动作）
1. `linning_server.py` 的 `_tools_payload()` 加定义（name / description / parameters）
2. `exec_library_tool()` 加分支，调 `memory_lib` 里对应的函数，返回一句话结果（会进 📖 日志）
3. 涉及"办成了"的写操作 → `CLAIM_MAP` 加触发词（judge 自动接管终审，不用写判定逻辑）
4. 沙盘跑通 → 备份 → 重启生效

### 菜谱 B：加一条 API 路由（app 多一个入口）
1. Handler 里加 `self.path == "/api/xxx"` 分支（POST 记得先读 body）
2. 数据逻辑写进 `memory_lib.py`（照 `_conn()` 函数模式，返回好打印的东西）
3. 沙盘 curl 实测 → 备份 → 重启生效；**接口形状只加不改**（§19 的契约）

### 菜谱 C：加一张表（家多一间房）
1. `memory_lib.init_db()` 加 `CREATE TABLE IF NOT EXISTS`
2. 文件头版本行照格式补（v0.1.2x …），写配套 add/get 函数（每函数自开 _conn 自关）
3. 要检索 → 挂一卷 FTS；要语义 → 挂 embed_queue；影子同步失败只打日志，绝不连累入库

**每一步通用流程**：备份进 档案馆/ → 沙盘验证 → 只加不改 → 遇阻 30 分钟封顶 → 落盘交接文档 §7。
